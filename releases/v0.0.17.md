# camt053-loader-mt940 v0.0.17

The first repository brought onto the **suite conformance gate**, and the
template for the other 31.

## Why this release exists

An audit of every repository in the suite found the same class of defect
throughout: things invisible from inside the repository that carries them,
which fail only for the user. No repository shipped `benches/`. Thirteen had
no `docs/`. Seven had no coverage gate at all. One had published a release
whose `__version__` reported the previous one.

A one-time sweep would fix those and then drift. This release adds the gate
that stops it.

## What changed

- **`tests/test_suite_conformance.py`** — 33 invariants shared across the
  suite, vendored from one canonical copy and checksummed by its own test.
  Editing the local copy fails by design, so no repository can quietly
  weaken a shared gate. Every assertion names a failure the suite has
  already shipped.

- **`benches/bench_parse_mt940.py`** — throughput across entries per
  statement and statements per file. It asserts no timing threshold, because
  wall-clock numbers are not comparable between machines. It exposes shape:
  `ns/entry` stays flat if the parser is linear, and climbs if it has gone
  superlinear — the failure no unit test sees and a month-end file finds.

- **`tests/test_regression.py`** — every documented claim, pinned, with the
  examples and the benchmark executed.

- **`docs/index.md`** and **`CONTRIBUTING.md`**.

## Two corrections to the documentation

Writing the regression tests found that the draft documentation described an
API that does not exist. `document.all_entries` and
`statement.entries_with_reason` are methods, not properties, and the latter
takes a reason code.

More importantly, the `parse_mt940` docstring overstates what it rejects. It
says a `ValueError` is raised "if a required field is missing". **Only `:20:`
is actually required.** A statement with no `:25:` parses successfully into
an account whose IBAN and BIC are both `None` — entries belonging to no
account, which reconcile against nothing and surface as an unexplained break
rather than a parse error.

The behaviour is unchanged in this release. Tightening it would break anyone
relying on the leniency, and that deserves to be a decision rather than a
quiet edit. It is now documented as a hazard with the defensive check spelled
out, and pinned by a test so any future change is deliberate.

## Verification

74 tests pass, up from 19, at 100% branch coverage. `ruff check`,
`ruff format`, `mypy` and `interrogate` are clean, now including `benches/`.
The regression suite and the conformance checksum were both mutation-tested.

## Compatibility

No API change. No behaviour change.
